# Profile maintenance

Notes for whoever edits this profile. Nothing here is linked from the README on purpose:
visitors see the result, maintainers read this.

## Layout

| Block | Source | Notes |
|---|---|---|
| Typing header, badges | `scripts/build_visuals.py` | Centered 680px SVG. SMIL typewriter; the first line is what non-animating renderers and reduced-motion visitors see. |
| About me | `README.md` (plain Markdown) | Edit the text directly. |
| Tech stack and desk setup | `scripts/build_visuals.py` (`BUILD`, `LEARNING`, `SETUP`) | Floats right of *About me* (`align="right"`, cleared by `<br clear="both">`). Keep the text column roughly as tall as the image. |
| GitHub stats (four cards, two badges) | `scripts/update_stats.py` | Generated by the workflow, 416px wide each. |

Two 416px cards fit GitHub's 846px profile column side by side. On narrower windows and phones they stack and
scale down, so no HTML tables are used. Each image uses a `<picture>` with light and dark sources, which GitHub
switches according to the visitor's theme.

All images are committed SVGs with system fonts and embedded paths. Visitors' browsers never contact a badge,
typing, icon or stats service. Brand icons come from Simple Icons (CC0), pinned in `assets/vendor/simple-icons.json`
with the licence alongside it; SQL, Oracle, data structures and the device icons are simple line glyphs drawn
in `scripts/profile_svg.py`.

Keep the identity year-independent, keep coursework separate from project experience, and never add credentials,
network addresses or private configuration.

## Editing the static artwork

```sh
python3 scripts/build_visuals.py          # regenerate assets/profile/
python3 scripts/build_visuals.py --check  # what CI runs: fails if SVGs are stale or obsolete
python3 -m unittest discover -s tests -v
```

Python 3.9+ standard library only, works offline. Commit the regenerated SVGs together with the script change.

## Statistics

`scripts/update_stats.py` makes one GraphQL query (paginated over repositories) using the workflow's built-in
`GITHUB_TOKEN`; no personal access token is needed. Definitions:

- **Stars, repositories, languages:** public repositories owned by `majianyu2007`, forks excluded, archived included.
- **Most used languages:** every repository is weighted equally and split by its own byte shares. Raw byte totals
  would let one repository with vendored C/C++ dominate. Build-file languages (CMake, Makefile, Dockerfile, …) are ignored.
- **Commits, contributed to, contributions, streaks, activity:** GitHub's contribution calendar for the last
  12 months, as GitHub reports it (private contributions appear only as counts, if the account shows them).
  Streaks are within that window, not lifetime records. A streak still counts as current if the last active day
  was yesterday, because today may not have started yet.
- **Pull requests, issues, followers:** totals as GitHub reports them.

`assets/stats/github-stats.json` holds the aggregated snapshot only (no tokens, no response bodies).
`python3 scripts/update_stats.py --render-only` re-renders the SVGs from that snapshot without network access,
which is handy when changing the card design. A local full run needs a token:
`GITHUB_TOKEN=$(gh auth token) python3 scripts/update_stats.py`.

## Workflow

`.github/workflows/update-stats.yml` runs daily at 06:23 UTC, on manual dispatch, and on pushes to `main` that
touch the scripts, artwork, tests or workflow. It checks the static artwork, runs the tests, regenerates the stats,
and commits only `assets/stats/` as `github-actions[bot]`.

Failure behaviour: the script validates everything and renders in memory, then swaps all files at once. Any
network, API or validation error exits non-zero before files change, and nothing is committed, so the README keeps
showing the last good images. If `main` moved during the run, the stats commit is rebased once and pushed again.

If a run fails:

1. Open the run in the Actions tab; the log names the failing step but never prints tokens or API responses.
2. Check *Settings → Actions → General*: Actions enabled, and workflow permissions not restricted by a policy
   (the job requests `contents: write` itself). Branch protection on `main` would block the bot's push.
3. Re-run with *Run workflow* once fixed.

GitHub pauses scheduled workflows after 60 days without repository activity. The daily stats commits normally
count as activity; if the schedule is ever disabled, re-enable it in the Actions tab.
